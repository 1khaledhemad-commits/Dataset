# Data architecture and enforcement boundaries

**Status:** bounded offline pilot, not a deployed or corpus-validated production service. The Python package uses only the standard library. Its purpose is to make rights, provenance, workload limits, and quality decisions explicit and inspectable—not to provide legal, factual, or semantic guarantees.

## End-to-end flow

1. **Governed source registry** — `config/source_registry.yaml` records provider URLs, assets, revision/evidence, language/domain/task metadata, source risk/trust, license scope, separate `training_use` and `evaluation_use`, redistribution, attribution, restrictions, privacy risk, rate-limit notes, and eligibility. The file uses JSON syntax (a safe YAML 1.2 subset) and is parsed with duplicate-key rejection. Registry validation rejects malformed fields, unsafe asset names/URLs, unsupported encodings, and evaluation-only assets assigned a non-evaluation purpose.
2. **Purpose gate and plan** — `src/data_platform/sources.py` requires an `APPROVED` or `APPROVED_WITH_RESTRICTIONS` decision, purpose-appropriate permission, acceptable trust/privacy status, and documented restrictions. `sources discover` is registry-metadata ranking only; `plan` is non-network and non-writing. The current registry has 13 candidates, one registered real asset, zero eligible assets, and one blocked asset.
3. **Bounded acquisition** — `src/data_platform/acquisition.py` permits HTTPS to the configured GitHub host allowlist (loopback HTTP is test-only), validates every redirect, paces/retries boundedly, honors safe resume validators, checks declared/transferred bytes, disk reserve, raw/per-source quotas, and verifies expected hashes or pinned Git blob SHA-1 where available. It validates payload structure before exclusive atomic promotion. Raw data are immutable; refresh-in-place is refused. Raw manifests record the source URL/host, revision, byte count, local SHA-256, upstream checksum basis, and time. Audit events omit full URLs, bodies, and credentials.
4. **Extraction** — `src/data_platform/extraction.py` supports bounded JSON, JSONL/NDJSON, CSV/TSV, UTF-8 text/HTML, gzip, ZIP, and tar text members. Archive members are not extracted to filesystem paths; traversal, links, nested archives, unsupported content, oversized payloads, and record/expansion overages are rejected. GitHub base64 blob extraction verifies the Git object SHA-1 and can make a deterministic, bounded priority sample. The pinned GSM8K asset proposes 100 records from a scan of at most 10,000 rows, but it is currently ineligible and has not been downloaded.
5. **Normalized record contract** — `src/data_platform/models.py` defines versioned extracted, normalized, validation, quality, and raw-manifest structures. `src/data_platform/normalization.py` applies NFC and CRLF/CR-to-LF only; Arabic diacritics, punctuation, letter variants, casing, indentation, and spacing are retained. Stable IDs derive from source ID, source-record ID, normalized content hash, and normalization version. Script proportions produce uncertain `ar`/`en`/`mixed`/`other`/`unknown` labels; they are not a validated language-identification model.
6. **Structural and quality gates** — `src/data_platform/validation.py` checks required types, schema/normalization versions, record/content SHA-256, time-zone timestamps, NFC/LF, confidence/composition ranges, and JSON-serializable metadata. The CLI and pipeline bound JSONL byte and record counts. `src/data_platform/quality.py` reports separate task, completeness, information-density, formatting, language, trust, license, privacy, and structure dimensions. It rejects invalid records, quarantines detected secrets/unsafe artifacts, sends possible PII and unknown language to review, and uses task-specific minimum lengths. Passing a heuristic gate does not mean factual/legal validation.
7. **Deduplication and splits** — `src/data_platform/deduplication.py` groups exact hashes of normalized content and uses word-shingle Jaccard for near-duplicates. It is not semantic deduplication; near comparisons require matching task and language and skip programming tasks. The O(n²) pairwise implementation is capped at 2,000 records. Decisions and deterministic cluster IDs are retained. `src/data_platform/splitting.py` hashes a seed and protected group into train/validation/test/evaluation assignments. A supplied duplicate cluster (or record ID) stays in one split; evaluation-only and evaluation-purpose records cannot enter train. Hash-threshold splits are reproducible but small sets can miss a target split.
8. **Candidate and release** — `src/data_platform/releases.py` creates an atomic, immutable directory with per-file SHA-256, a SHA-256 of the manifest, a completion marker, source/license decision summaries, counts, split/quality/dedup metadata, and third-party notices. The verifier rechecks limits, record structure, content hashes, files, license/purpose consistency, provenance, duplicate hashes, evaluation separation, and human-approval metadata. Manifest hashes are not signatures.
   - Fixture smoke runs may publish fixture-marked split files solely to prove the offline test path.
   - A real `run` writes a **manifest-only candidate** while approval is pending; its curated/split JSONL remains in private staging. It does not put real records in the release directory.
   - The manual `release` CLI is the only supported publication path. It derives rights and provenance from the current registry rather than caller-supplied decisions; it requires explicit `approved` status, approver, and approval reference, and it rechecks quality/safety, pairwise duplicates, purpose-specific rights, and resource limits.
9. **Reports and audits** — `src/data_platform/reporting.py` records observed bytes/counts/timings/peak RSS/outcomes, not estimated corpus yields. `src/data_platform/audit.py` keeps a privacy-minimal append-only JSONL log with a 16 MiB default log limit and 64 KiB event limit. OS file locking prevents concurrent quota races where `fcntl` is available. The local log is not remote, signed, or tamper-proof.

## Data boundaries and key paths

- `data/raw/<source>/` — immutable downloaded bytes and sidecar manifests.
- `data/staging/runs/<run-id>/` — private intermediate JSONL, quality assessments, decisions, and split records; this is not a released training corpus.
- `data/quarantine/` — records requiring review and rejected/unsafe partial files; access should be restricted and retention set by operators.
- `data/releases/<release-id>/` — only completed fixture releases or explicitly approved real releases. Real pipeline candidates have `manifest_only: true` and no split data files.
- `logs/audit.jsonl` — local append-only operational events; never intended to contain record text, full URLs, or secret values.
- `reports/runs/<run-id>/` — observed run report JSON/Markdown.
- `config/source_registry.yaml`, `config/pipeline.json`, `tests/fixtures/`, `docs/licenses/` — versioned project inputs/evidence.

Generated data and reports are ignored by Git. Operators must protect local raw/staging/quarantine data with filesystem permissions, backup/retention controls, and an appropriately access-controlled deployment environment.

## Provenance and integrity limits

Each normalized record carries source ID/record ID, source URL, source revision, license identifier, ingestion timestamp, normalization version, content hash, attributes, and a provenance object tying it to an asset ID and raw artifact hash. Release manifests cross-check those values against source/license manifests. A Git SHA-1 is used only as the upstream Git object identifier for the pinned GSM8K blob; the local SHA-256 identifies the downloaded API response bytes. Neither a local hash nor a manifest stored beside its data proves who authored or approved that data.

## Current verification boundary

The offline fixture path has been executed end to end. No real source payload has passed acquisition, no corpus-level quality or Arabic-language benchmark has been run, no production infrastructure has been deployed, and no full human review has occurred. See `docs/project_log.md` and `docs/implementation_report.md` for observed results and blockers.
